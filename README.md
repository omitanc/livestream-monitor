# LiveStream Monitor

YouTube Liveを視聴側から確認する、macOS / Windows向けElectron＋TypeScriptアプリです。
現在は **0.1.0 開発プレビュー**。Macで表示・画像取得・リロードを検証するための初版です。

## 起動

Node.js 22.12以降（または24以降のLTS）とnpmが必要です。

```sh
make setup
make run
```

Makeを使わない場合（Windows含む）:

```sh
npm ci
npm exec install-electron
npm run dev
```

Electronの実行ファイルは公式配布元から取得します。グローバルインストールは不要です。

1. 「管理」→「ローカル検証」で時計と動く図形の検証画面を開く、または自分のYouTube動画URLを入力して「配信を開く」。
2. YouTubeの再生を確認して「取得を開始」。毎秒およそ1回、動画フレームを直接取得します。
3. 「再読み込み」「ライブ位置へ」、任意の1〜180分間隔の自動リロードを試せます。
4. 「管理」→「死活監視・通知の設定」で、判定条件・継続時間・判定範囲・警報音・OS通知を設定して保存します。CPU・メモリ・キャッシュ・更新の操作も「管理」内にあります。

**取得中＝配信正常ではありません。** 死活監視は選択した条件だけを確認します。映像全体の変化率と、指定した判定範囲の変化率を分けて表示します。
時計OCR・時刻による遅延判定・特定色の判定・スマホ通知は未対応です。
無人の本番監視には使用しないでください。

## 初版でできること

- 隔離したWebContentsViewでYouTubeの動画のみを表示。動画の縦横比に追従し、ミュート/解除をアプリから操作できます。
- YouTubeの字幕・操作UIを含まない動画フレームの低頻度取得、最新画像・取得時刻・変化率・プレーヤー状態の表示。YouTubeの再生エラー画面も観測不能として扱います。
- 手動/定期リロード、ライブ位置への移動要求（復旧の自動判定は未実装）。
- 時計停止・図形停止・黒画面を切り替えられるローカル検証画面。
- 映像停止、再生停止/終了/読み込み待ち、黒画面、観測不能の継続判定。条件ごとに有効/無効と1〜3600秒の継続時間を設定できます。
- 異常時のPC警報音、OS通知、確認して消音、復旧通知。警報音量・繰り返し間隔と、映像停止/黒画面の判定範囲を設定できます。
- 監視・通知設定の保存と次回起動時の復元。
- 同時1件・待ち行列なしの画像取得、履歴100件、最新画像のみメモリ保持。
- HTTPキャッシュの容量表示・手動削除。Cookie等のログイン情報は削除しません。
- GitHub Releases＋electron-updaterの更新UIと配布設定の土台。

## 監視・通知の使い方

「管理」または死活監視パネル右上から設定を開きます。選択した条件のいずれかが指定秒数続くと、画面を赤く表示して警報を出します。

| 条件                         | 初期の継続時間 | 判定                                                                      |
| ---------------------------- | -------------- | ------------------------------------------------------------------------- |
| 映像の変化が少ない           | 60秒           | 指定範囲の変化した画素が0.5%以下                                          |
| 再生停止・終了・読み込み待ち | 15秒           | プレーヤーの停止/エラー/バッファ不足、または再生時刻が2秒以上進まない状態 |
| 黒画面                       | 30秒           | 指定範囲の98%以上が明るさ16以下                                           |
| 観測不能                     | 15秒           | 画像取得失敗、または5秒以上新しい観測がない状態                           |

開始直後は15秒待ち、復旧は5秒継続して確認します。各値は変更できます。リロード中の欠測は復旧とは扱わず、判定の継続時間を保持します。判定条件を保存し直した場合は、新しい設定で判定を開始します。

時計やテロップが動き続ける配信では、左・上・幅・高さの割合（%）で本編だけを指定できます。映像取得中は最新画像に判定範囲を重ねて表示します。静止画や暗いシーンを配信する場合は、対応する判定条件を調整するか無効にしてください。

PC警報音は「確認して消音」、復旧、取得停止まで繰り返します。映像のミュートとは独立しています。同じ異常のOS通知は繰り返さず、新しい条件が確定したとき、または復旧後の次の異常で再通知します。「警報音を試す」「OS通知を試す」で保存済み設定と環境を確認できます。

OS通知は通知許可や集中モードの影響を受けます。macOSでは署名済みアプリが必要です。現在の開発用Electronでは表示失敗を確認しており、画面とイベントに失敗を表示します。署名・配布の実装はまだ行っていません。

## 制約とデータの扱い

- **実ライブの最小化中の連続再生は未保証**。今回のMac検証では観測不能に移る場合がありました。初版は通常表示で検証してください。
- PCロック・スリープ・長時間稼働・Windows実機は未検証。スリープ通知を受けると取得を停止し、復帰後は手動で開始します。スリープ防止は行いません。
- YouTube側のUIは非表示のため、ログイン・同意などのページ操作には対応しません。ポップアップ・ダウンロード・カメラ等の権限は拒否します。
- 動画フレームを直接取得できない場合は観測不能とし、ページ画面の取得には切り替えません。映像自体に焼き込まれた字幕・ロゴは映像の一部として表示・取得します。
- 監視・通知設定はアプリの`userData/monitor-settings.json`へ保存します。入力URL・画像・異常履歴は保存しません。再起動後の監視開始は手動です。ページ情報はChromiumのキャッシュ等へ残る可能性があります。
- アプリ専用プロファイルはElectronの`userData`配下。普段のChromeプロファイルとは別です。Cookie等はアプリプロファイルに保持されます。
- HTTPキャッシュの目安は256 MB（Chromiumへの指定）。Cookie、GPUキャッシュ、更新ファイル等を含む全保存量の厳密な上限ではありません。
- 開発版では更新確認が説明表示になります。署名済みの旧版→新版の更新、設定保持・監視再開は後続実装/検証です。実際のリリース公開は行っていません。
- Healthchecks.io / Pushoverは候補のまま、未登録・未接続。秘密情報をGit・ドキュメント・ログへ書き込まないでください。

## 開発と検証

```sh
npm run build       # 型チェックとバンドル
npm test            # URL/IPC・取得制御・監視判定・設定保存・通知の回帰テスト
npm run test:smoke  # ビルド済みのElectronを起動するローカル検証（GUIセッションが必要）
npm run lint        # 型とフォーマット
npm run fmt
npm run package    # 公開せずローカル向けにパッケージ化
```

`test:smoke`は一時プロファイルを作成し、終了時に削除します。外部の配信URLは使用しません。
`LSM_QA_DIR`を指定すると、初期画面・管理画面・取得状態のスクリーンショットを保存します。
通常のPlaywrightページスクリーンショットにはネイティブ子ビューが含まれないため、実際の映像表示はネイティブウィンドウでも確認します。

- `src/main/`: Electron、取得・リロード・更新
- `src/preload/`: ローカルGUIに限定したIPC
- `src/shared/`: 型・検証・取得スケジューラ
- `src/renderer/`: React GUIとローカル検証画面
- `tests/`: 回帰テスト
