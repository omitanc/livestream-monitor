# 初版の検証記録

日付: 2026-09-28〜29。macOS 26.6.2 / Apple Silicon arm64 / Electron 44.4.5。
Windows実機では未実施。初版は表示・取得・操作の検証用で、無人監視向けの完成版ではない。

## 確認したこと

- TypeScriptの型チェック、Vite/esbuildのビルド。
- URL・IPC検証、画像差分、取得の同時実行制限・タイムアウト、ページ遷移と自動リロード、再生エラー画面のユニットテスト29件。
- Electronのローカル検証: 起動→管理→開発版の更新ガード→ローカル映像→取得→最小化→取得継続→復元→リロード→再取得→停止→HTTPキャッシュ削除。
- 指定された外部ライブでYouTubeページの表示・動画再生・時計映像の領域キャプチャを確認。指定URLはコード・設定・この記録に保存していない。
- 外部ライブで手動リロード、1分間隔の自動リロード、その後の画像取得再開を確認。ライブ位置への移動要求は実行できたが、時計OCRによる遅延の復旧判定は未実装。
- ローカル検証は最小化中も取得できた。実ライブは最小化中に途中で観測不能となり、通常表示でも一時的な再生中断が発生。観測不能を正常とは表示せず、リロード後は再取得できた。
- CPU/メモリ/キャッシュ表示を確認。実ライブ再生時の関連プロセスのメモリ合計は約1.3〜1.5 GBの観測例があり、軽量性の受け入れ基準を満たしたとは扱わない。共有メモリの重複等を含みうる合計値で、長期測定ではない。
- npm auditは開発依存を含め指摘0件（照会時点）。

## GUI検証

- 内蔵ブラウザでローカルGUIの表示、実ElectronウィンドウでYouTubeと時計の表示を確認。
- 内蔵ブラウザの全体スクリーンショットが取得できなかったため、Chrome＋Playwrightでも検証。1536×1024と390×844で確認し、ページ識別、空白でないこと、フレームワークエラーがないこと、管理画面の開閉、ブラウザ専用説明の表示、横はみ出しなしを確認。
- `docs/design/monitor-concept.png`と最新の実装スクリーンショットを画像表示ツールで比較。
- 一時スクリーンショットはリポジトリに含めない。再現時は `LSM_QA_DIR` を指定できる。

| 配置     | URL欄、左の映像と履歴、右の状態と操作の順序を維持                                        |

意図的な差分: ネイティブのOSタイトルバー、実際のプレーヤー状態、動的なエラー文、ブラウザプレビュー表示、小さい画面での1列配置。生成案の偽ウィンドウボタンは実装しない。低いウィンドウでは映像枠の高さを調整する。デザイン案の構成・配色・操作階層に沿った実装として確認した。

## 修正した不具合

- YouTubeの子フレーム読み込みが全体の取得待ち状態を残す問題: メインフレームのドキュメント遷移だけを扱い、回帰テストを追加。
- 子フレームのリダイレクトまでページ遷移制限の対象にしていた問題: 外側のページ遷移だけを許可リストで制御し、回帰テストを追加。
- ページ読み込みが終わらない場合の無期限の取得待ち: 取得開始中は15秒を超えたら観測不能表示。
- 幅の狭い画面で映像枠がはみ出す問題: 明示的なwidth指定を追加。
- YouTubeの再生エラー画面で`HTMLMediaElement.error`が空のため「一時停止」と表示される問題: 可視のエラー表示を検出し、再生エラー/観測不能へ切り替える。回帰テストを追加。2026-09-29にビルド、lint、29件のテストとElectronスモークテストを通過。実ライブでの再発確認は未実施。

## 次の優先事項

1. 実ライブの再生中断を切り分け、通常表示・最小化・他ウィンドウで覆った状態・PCロックで継続取得を安定させる。非表示時の描画抑制を解除しても、現時点では安定性を保証できない。
2. 時計/本編/色判定の領域指定、OCRと遅延、判定状態と継続時間、限定回数の自動復旧。
3. 設定保存・再起動後の復帰、警報と外部通知・heartbeatの接続。
4. 長時間のCPU/メモリ/保存量の測定と削減、Windows検証、署名済みリリース間の更新検証。

初回YouTubeロード時のエラーや再生中断の原因は未特定。ネットワーク、プレーヤー側、アプリの非表示挙動を分離して調べる。再起動・スリープ・通知到達・署名済み更新・長時間耐久を検証済みとは扱わない。
