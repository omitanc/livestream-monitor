# プロジェクト引き継ぎメモ

更新日: 2026-09-28

## 確定した要望

- 自分のYouTube Liveを、配信者側ではなく視聴者側から監視する。
- 最初はYouTube Live専用。将来のニコ生・X・Instagram Live・Twitch対応は今回の範囲外。
- 専用アプリ内にYouTubeを表示する構成を第一候補とする。Chrome拡張機能などとの比較・技術検証を行い、採用方式を確定する。
- macOSとWindowsの両方で使用できるようにする。
- 配信映像には秒単位のデジタル時計を入れられる。時計の更新停止と視聴遅延を検出する。
- 映像本体のフリーズ、指定領域の黒画面・特定色がn分続く状態も検出する。時計が動いていてもカメラだけ止まる場合がある。
- YouTubeの視聴側がライブ位置を失うことがあるため、設定可能なn分間隔のページ再読み込みと、異常時のライブ位置への復帰を検討する。
- 異常時には監視PCで警報音を鳴らし、外出中にも届く緊急通知を行う。
- 監視PCやアプリの停止は、自前サーバーを立てず既存の外部API/サービスで検知したい。

## 検討中の設計（未確定）

- アプリ内表示の候補はElectron等。YouTubeの視聴・ログイン・再生、ページ画像取得、再読み込み、最小化時の動作をmacOS/Windows双方で検証してから決める。Electronで外部ページを表示する場合、Node integrationを切り、context isolationを有効にする。
- 送出PCと監視PCの時刻を合わせ、時計表示をOCRなどで読む。時刻差から遅延を測り、通常の配信遅延を基準として閾値を設定する。OCR不能は別状態。
- 本編のフリーズ判定から時計・コメント・操作UIを除外する。黒画面判定は指定領域で行う。再生停止・配信終了・広告・観測不能を区別する。
- 自動復旧は「ライブ位置へ戻る → ページ再読み込み → プレーヤーまたはアプリ再起動」を候補とし、回数を制限する。リロードは障害の継続時間を無条件にリセットしない。復旧後は時計と映像で確認する。
- Healthchecks.ioで監視処理の定期ping欠落を検出できる。PC停止、アプリ停止、回線断のどれかは外部から区別できない。監視処理の稼働と配信の正常性を別チェックにする候補。
- PushoverのEmergency通知は確認まで再通知できる。ローカル警報音とスマホ通知を分け、消音・確認・テスト再生・復旧通知を設ける。Healthchecks.ioとPushoverの連携も候補。
- 設定値、通知先、APIの認証情報は機密として扱い、Gitに記録しない。

## 技術検証と受け入れ条件

- 配信映像の時計停止、映像本体だけの停止、黒画面、意図的な静止画、視聴遅延、広告、配信終了、ログイン切れを識別する。
- ページ再読み込み、ライブ位置への復帰、アプリ再起動で解析が継続する。
- 最小化、PCロック、スリープ、ネットワーク断、監視アプリ終了時の挙動をMac/Windows実機で確認する。
- 異常検出からPC警報音とスマホ通知まで通しで試し、復旧通知と通知の重複抑制も確認する。
- 閾値やn分間隔は初期値を仮置きし、実配信の遅延・画面内容を見て調整する。
